HOW MODES WORK (important — the board has NO PSRAM, ~103 KB free heap):
  The receiver allocates one decoder per registered protocol at Sub-GHz app
  entry, so the General set and the Automotive set CANNOT be resident at the
  same time. You switch between them:

      Sub-GHz  ->  Radio Settings  ->  Automotive  =  ON / OFF

  OFF (default) = GENERAL set below.   ON = AUTOMOTIVE set below.
  RAW + BinRAW appear in BOTH modes so any undecoded signal can still be
  captured and replayed.

LEGEND:
  [TX]  = decode AND emulate/transmit (has an encoder)
  [RX]  = decode / read only (no transmit)
  [CAP] = raw capture + replay (no protocol decode)

--------------------------------------------------------------------------------
  NOTES
--------------------------------------------------------------------------------
  * KeeLoq / KIA / Fiat / VAG / PSA rely on key material loaded at RUNTIME from
    the microSD:  E:\subghz\assets\keeloq_mfcodes_user  (227 keys).
    If that file is missing/stubbed, KeeLoq falls back to the 4-key system file
    and KIA automotive decode breaks. Keep it in sync with the port master:
      applications\main\subghz\resources\subghz\assets\keeloq_mfcodes_user
  * Automotive car encoders are RF-UNTESTED (simulation round-trips only) and
    are RKE (unlock/lock/ID) — not engine immobilizer (that's 125 kHz LF, no HW).
  * Rainbow-table protocols (Nice FloR-S, Alutech AT-4N) ship IV-header assets
    only in this port.
