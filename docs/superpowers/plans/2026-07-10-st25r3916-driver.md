**Goal:** Implement an ST25R3916 backend for the port's `furi_hal_nfc` API so the M5Stack NFC Universal Unit works — unblocking read/write/emulate, mfkey nonce collection, and magic-card writing on the user's real hardware.

**Architecture:** Vendor Flipper's ST25R3916 register driver + `furi_hal_nfc` event/transceive core (GPLv3), swap STM32 SPI/GPIO/timer for ESP-IDF (SPI + a GPIO-ISR IRQ path raising `FuriHalNfcEvent`), add board pins, and make the NFC backend selectable (ST25R3916 vs the existing PN532). Upper NFC stack (`components/nfc/`) unchanged.

### Task 1: Hardware bring-up + backend-select scaffolding — ✅ DONE (commit a3fad76)

**HARDWARE RESOLVED (M5Stack NFC Universal Unit product page):** the unit is **I2C @ 0x50** (100K/400K) on the **Grove 4-pin** (SDA/SCL/5V/GND) — **NOT SPI**, and **NO IRQ line** is broken out. It shares the existing `BOARD_NFC_I2C_PORT` (same pins as PN532, different device addr). So: NO SPI, NO hardware interrupt — the event model must **poll the ST25R3916 IRQ status registers** (main 0x1A / timer 0x1B / error 0x1C). This is exactly the synchronous style the PN532 adapter already uses.

Done in a3fad76:
- Vendored the REAL ST25R3916 register map (`components/furi_hal/st25r3916/st25r3916_reg.h`, from Flipper `lib/drivers/st25r3916_reg.h`, GPLv3). IC_IDENTITY (0x3F) `ic_type` for ST25R3916 = **0x05** (`5<<3`), derived from the header macro (not hardcoded).
- `st25r3916_i2c.{c,h}`: I2C protocol (mode-byte: reg-write=`reg&0x3F`, reg-read=`|0x40`, direct-cmd=`|0xC0`, space-B via 0xFB) + `read_reg`/`write_reg`/`check_chip_id`/`st25r3916_probe`, on the shared NFC I2C bus @ 0x50.
- Board defines `BOARD_HAS_ST25R3916 1` / `BOARD_ST25R3916_I2C_ADDR 0x50`. PN532 backend untouched (still active).
- Callable but NOT yet wired into `furi_hal_nfc.c` (that swap is Task 2).

### Task 2: Vendor + port the ST25R3916 driver + furi_hal_nfc backend

**(Brainstorm/sub-plan this task in detail before coding — it's the bulk.)**

- [ ] Vendor (GPLv3, keep headers) the Flipper `lib/drivers/st25r3916*.{c,h}` register driver and the `furi_hal_nfc` event/transceive core (`furi_hal_nfc_i.c` + the `_iso14443a/_iso14443b/_iso15693/_felica` tech modules) into `components/furi_hal/st25r3916/` (or similar). Namespace/adapt to avoid collision with the existing furi_hal_nfc.c.
- [ ] Replace STM32 dependencies with ESP-IDF (use the Task-1 `st25r3916_i2c.{c,h}` layer — I2C @ 0x50, NOT SPI):
  - Register/FIFO read/write → the Task-1 I2C helpers (extend with FIFO read/write + direct-command helpers using the same mode-byte protocol).
  - **NO hardware IRQ (Grove 4-pin has no IRQ line): POLL the ST25R3916 IRQ status registers** (main 0x1A / timer 0x1B / error 0x1C) in the NFC worker loop and synthesize the `FuriHalNfcEvent` bits from them. Model this on how the PN532 adapter (`furi_hal_nfc.c`) synchronously fakes the event system — but here the ST25R3916 genuinely does the RF work on-chip (FIFO + auto-transceive), so polling the completion IRQ regs over I2C is the correct pattern. Configure the ST25R3916 IRQ MASK regs so only needed IRQs latch.
  - Timers: the chip's on-chip FWT/GPT set the timer IRQ bits → map to `FuriHalNfcEventTimerFwtExpired` when polled.
  - Consideration: I2C @ 400K + register polling adds latency vs SPI+IRQ; acceptable because the chip handles µs-scale RF timing internally. Validate throughput on real captures.
- [ ] Implement the full `furi_hal_nfc.h` surface on top of the ported driver: init/ready/acquire/release, set_mode(Poller/Listener), tech config, poller_tx/rx, listener_tx/rx, **custom-parity/short-frame** (needed for magic Gen1a + mfkey), abort.
